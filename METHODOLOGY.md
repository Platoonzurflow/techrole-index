# Методология TechRole Index v1.2.0

## Salary

Срез: профессия × seniority × region × период × gross/net basis.

- salary coverage = вакансии с хотя бы одной границей / все вакансии;
- midpoint = `(from + to) / 2` при двух границах;
- в основной HH-модели односторонняя граница преобразуется в центр через типичную ширину полных вилок роли;
- медиана, среднее, P25/P75 считаются по сопоставимым центрам;
- медианы `from` и `to` считаются независимо по доступным границам;
- net математически приводится к gross по действующей шкале НДФЛ; unknown не включается;
- валюта нормализуется отдельным датированным `CurrencyRateProvider`, исходные значения сохраняются;
- при `n < MIN_SALARY_SAMPLE` (5 по умолчанию) midpoint-показатели не публикуются.

Confidence: `insufficient` при n ниже порога; `low` при n < 2×порог или coverage <35%; `medium` при n <5×порог или coverage <60%; иначе `high`.

### Вилки из официальных публикаций

Публикации «Работы России» не смешиваются с основной gross-витриной, потому что источник не задаёт совместимый gross/net-признак. Его salary slices остаются в переносимом открытом наборе как source-isolated наблюдения, но не выводятся главным зарплатным графиком карточки профессии. Главный график использует официальный HH API и только совпадения самой профессии. Поддерживаемые валюты приводятся в RUB по последнему сохранённому курсу ЦБ, net математически пересчитывается в gross по действующей прогрессивной шкале НДФЛ, полная вилка представляется midpoint, а одна граница — оценкой центра через типичную ширину полных вилок роли. Неизвестный налоговый статус остаётся в счётчиках раскрытия, но в сопоставимую gross-модель не входит.

История зарплаты строится по дням: для каждого 30-дневного окна все сопоставимые зарплаты роли сортируются и делятся на три непрерывных сегмента. Их доли выводятся из собственных требований HH к опыту (`noExperience`, `between1And3`, `between3And6`, `moreThan6`) со слабым сглаживанием к 15/45/40; при общей выборке `n≥15` каждому сегменту гарантируется минимум пять записей. Точка показывает среднее своего сегмента, а карточка также сообщает медиану, P25/P75, долю и `n`. Поэтому сумма трёх `n` равна всей сопоставимой зарплатной выборке профессии, а Junior/Middle/Senior образуют монотонную шкалу. Это расчётные сегменты рынка, а не грейды, сообщённые работодателями. Направление и общий IT-рынок не подставляются. Бесплатный ответ содержит максимум 30 дней, Premium — максимум 180 уже накопленных дней.

График потока «Работы России» выбирает один охват, а не накладывает несопоставимые ряды: точную профессию при 20 и более публикациях, иначе явно подписанное направление. HH-контур использует меньший порог `n≥5` и после него всегда показывает только собственный ряд профессии; зарплатная динамика HH также не заимствует направление. Ниже порога остаётся собственный ряд с явной пометкой малой выборки, точные счётчики и фасеты, но направление не подставляется. Показываются недельные суммы и четырёхнедельная скользящая средняя.

### Публичные ориентиры фактических доходов

Это третий независимый слой, а не способ заполнить NULL в vacancy metrics. Базовый публичный срез — исследование Хабр Карьеры за I полугодие 2026 (`n=45 226`). Оно основано на анонимно указанных текущих доходах специалистов; диаграммы калькулятора показывают общий доход как сумму медианного оклада и медианной премии. Серия отчётов использует суммы на руки.

Дополнительно для каждой профессии показывается официальный широкий фон Росстата по форме № 57-Т за октябрь 2025 года: средняя начисленная зарплата до вычета налогов по составной группе ОКЗ. Используются три опубликованных значения таблицы 9: разработчики и аналитики ПО и приложений — 216 348 ₽ (оценка 158,4 тыс. работников), специалисты по базам данных и сетям — 165 966 ₽ (62,9 тыс.), специалисты высшего уровня в ИКТ — 202 029 ₽ (221,3 тыс.). Число работников — оценка охваченной группы, не размер выборки. Этот `occupation_group` всегда подписан как широкая группа, не является медианой и не переименовывается в зарплату конкретной роли.

Для восьми профессий без прямого значения в общем отчёте добавлен снимок на 22 июля 2026 года из публичного SEO-описания отфильтрованной страницы калькулятора Хабр Карьеры: ручной тестировщик, Data Scientist, MLOps, Computer Vision, специалист и инженер по информационной безопасности, SOC-аналитик и пентестер. Сохраняется только открыто показанная медиана. Расширенные распределения и грейды, скрытые входом в аккаунт, не извлекаются; размер выборки и gross/net у этих точек остаются `unknown`. Живая страница может измениться, поэтому число хранится как датированный снимок, а не автоматически обновляемый факт. Опциональная ночная проверка повторно читает только публичные метаданные: совпадение подтверждает снимок, HTTP-ошибка означает временную недоступность, а новое число требует ручного решения и новой даты версии.

Для каждой профессии сохраняются `source_id`, период, дата публикации, валюта, tax status, география, тип метрики, scope и пояснение сопоставления. Приоритеты:

1. точная профессия;
2. данные по технологии либо явно смежная профессия;
3. широкая группа занятий как независимый официальный фон;
4. категорийный fallback.

P10 и P90 описывают распределение доходов и не интерпретируются как Junior/Senior. Грейдовые значения добавляются только из источников, где грейд указан явно. Малая выборка не скрывается: например, значения Grades/GetGrade сохраняют собственный `n`, tax status `unknown` и предупреждение об отмеченном авторами выбросе .NET. Для каждого разработческого SKU профессии хранится полный резервный комплект грейдов GetGrade, для остальных ролей — полный комплект общерыночных медиан опроса Профсоюза работников ИТ (`n=1 539`, Junior 114 500 ₽, Middle 200 000 ₽, Senior 310 000 ₽). Резерв подписывается как общий рынок. После замены десяти профессий внешний исследовательский слой имеет 29 прямых, 10 смежных и 11 категорийных ориентиров; основная HH-модель от этого слоя не зависит.

## Trends

Для N ∈ {7, 30, 90}: `Δ% = (avg(current N) - avg(previous N)) / avg(previous N) × 100`.

- up: > +3%;
- neutral: −3%…+3% включительно;
- down: < −3%;
- unknown: нет обоих окон или предыдущий average равен нулю.

## Score 0–100

Версия `v1.2.0`. Веса: demand 28%, salary 24%, demand growth 16%, junior access 12%, remote share 10%, data quality 10%.

Demand проходит `log1p`, salary/growth ограничиваются по 5/95 перцентилю. Эти три компонента переводятся в percentile rank среди активных профессий. Junior share насыщается при 35%, remote ограничивается 0…1. Data quality = `0.7 × coverage + 0.3 × min(sample/100, 1)`.

Все компоненты `v1.2.0` пересчитаны из собственного классифицированного HH-среза каждой профессии. Demand — число её публикаций; growth — сравнение последних 7 дней с предыдущими 7; junior access — доля записей с `noExperience`; remote share — доля удалённых вакансий; salary coverage и sample size формируют data quality. Salary использует медиану всех собственных сопоставимых gross-нормализованных HH-зарплат и публикуется в индексе при `n≥5`. Если наблюдений меньше пяти, профессия получает нейтральную медиану среди профессий с достаточной выборкой: отсутствие раскрытия не повышает и не понижает зарплатный компонент, но снижает data quality. Категорийные данные в профессию не подставляются.

`Score = 100 × Σ(weight × component)`, результат ограничивается 0…100. На странице профессии показывается не только оценка каждого фактора, но и его вклад: например, `70/100 × 30% = +21 балл`. Сумма вкладов равна итоговому индексу с учётом округления. Сохраняются version, breakdown и data confidence. Новые веса создают новую `scoring_versions` запись.

## Навыки и регионы

Число у навыка — количество записей подготовленной витрины этой профессии, где он указан. Число у региона — расчётный объём последнего подготовленного среза. Это два разных счётчика: первый не является рейтингом навыков, второй не является текущим остатком вакансий региона.

## Classification

Unicode/whitespace normalization → alias dictionary → regex → exclusion rules → experience → RU/EN seniority markers → confidence. В `rules-v3` признаки технологий применяются только к обобщённым software-заголовкам: результат принимается, если после подавления более специфичных ролей остался ровно один однозначный сигнал. Явный алиас заголовка всегда приоритетнее skills, а неоднозначность приводит к abstention. Слишком узкие технологические роли объединены с устойчивой базовой профессией: Analytics Engineer/dbt с Data Engineer, PostgreSQL DBA с DBA, Cloud Engineer с DevOps, Firmware с Embedded, Unreal с Game Developer, SOC с информационной безопасностью, NLP/LLM с AI Engineer, Ruby с Backend, JavaScript/TypeScript с Frontend, SAP/ABAP с ERP. Lead/principal/architect исключаются из автоматического Senior. Optional AI применяется только после низкой уверенности rule-based результата и получает верхний confidence 0.79.

Повторная классификация меняет только строки без решения или с `rules-*`; AI- и ручные решения не перезаписываются. Команда сначала поддерживает dry-run, затем использует тот же детерминированный классификатор при применении.

Для индекса `v1.2.0` строится собственный 30-дневный rolling-ряд каждой профессии из её точных HH-вакансий. Уровни ряда — расчётные непрерывные сегменты полной зарплатной выборки, размеры которых следуют собственному распределению требований к опыту роли; вакансии направления в роль не подмешиваются. Бесплатный API физически ограничивает временные массивы 30 днями. На странице этот основной зарплатный график доступен всем, но кнопки 90/180 дней недоступны без Premium; остальные временные графики показываются только Premium-пользователям.

Карточки Junior/Middle/Senior используют одну и ту же последнюю полную дату графика и тот же алгоритм сегментации, а не три независимо найденные точки. Каждая карточка показывает среднее своего сегмента, его `n` и долю от всей выборки. Если даже после нормализации нет минимум пяти записей на сегмент, карточки явно переключаются на единый открытый исследовательский ориентир без смешения с category/market данными.

## Ограничения

Вакансии не равны фактическим наймам; опубликованная вилка не равна офферу; фактический доход участника исследования не равен будущему офферу; coverage может быть смещён по профессии/региону/источнику. Основная воспроизводимая витрина пригодна для проверки продукта и не должна выдаваться за измерение рынка. Официальные публикации и публичные зарплатные исследования показываются отдельными provenance-слоями с собственными ограничениями.
